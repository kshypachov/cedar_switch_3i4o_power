# Отчёт этапа P5 — логи и владелец UART

Критерий раздела 10: «Два источника, overflow и gaps, залипший браузер не блокирует
логгер, переключение владельца UART».

**Статус: сделан, не закрыт.** Критерий раздела 10 выполнен на плате B: два источника
одновременно, overflow с точным учётом потерь, wrap и gap, залипший клиент не задерживает
логгер (производитель ждёт не дольше копии одной записи; другой HTTP-клиент ждёт до таймаута
отправки 5 с), переключение владельца UART `console ↔ usb_bridge ↔ flashing` с маркерами и
поколениями. Открыты (раздел «Не сделано и открыто»): экспорт занимает поток HTTP на всё время
отдачи; голодание вытесняемых потоков после потока через мост к хосту в сценарии `uart`;
вывод C6 с уровнями ESP-IDF — до P6. Закоммичен в ветке `p5-logs`, не запушен.

Worktree `zephyr_latest/cedar_p5`, ветка `p5-logs` от `cedar_board/main` (`4582fe4`, merge P4).
Аппаратные проверки — только плата B (J-Link `000941000024`); плата A (ST-Link, сессия P3) не
затрагивалась: ни прошивки, ни сброса, ни открытия её портов, ни запросов.

## Дизайн (записан до кода; итоговые решения — в README модулей и в `api-contract.md`)

### log-store
- Два байтовых кольца (Kconfig, по 256 КиБ), записи переменной длины, выравнивание 4 Б:
  заголовок (seq u64, uptime_ms u64, generation u32, level, kind, truncated, длины
  module/text) + module ≤64 + text ≤512 + хвост с длиной (обход назад для «последних
  `limit`»). Позиции — абсолютные байтовые (u64 записано всего): запись по позиции `p`
  цела, если `p ≥ tail_abs` на момент после копирования.
- Один `k_mutex` хранилища: производитель под ним выдаёт глобальный seq, вытесняет
  старые записи, копирует новую — порядок фиксации = порядок seq. Читатель берёт тот же
  lock только на просмотр заголовков обоих колец и копию **одной** записи (≤608 Б) в свой
  буфер; фильтр, JSON и отправка — вне lock. Производитель ждёт не дольше одной копии.
  Спинлок отвергнут: маскировал бы прерывания на копию, а RX USART3 не должен ждать
  веб-клиента. ISR в кольцо не пишет. Вариант без lock (seqcount) отвергнут: гонки не
  воспроизводятся в sim и не проверяются мутациями. Время удержания измеряется на плате
  (`log_store_get_timing`).
- Cursor (opaque, base64url): версия, тег boot (FNV `boot_id`), хеш фильтров, позиции
  обоих колец, контрольная сумма. Позиция `< tail` → gap; позиция `> head`, плохая сумма,
  чужие фильтры, пустой cursor → 400 `invalid_cursor`; **чужой boot → как без cursor
  (последние `limit`), новый boot_id, `gap=true`** (контракт: «текущий хвост»). Mock сейчас
  отвечает на такой cursor 400 (`boot_id` в хеше фильтров) — выровнять.
- Панический режим backend: после `log_panic()` `process()` идёт синхронно в контексте
  отказа (возможно ISR) — backend только считает потерю, lock не берёт.
- Чтение ограничено числом просмотренных записей за запрос (cursor продолжает
  сканирование) и байтами ответа (`has_more`).
- Экспорт — итератор кусками под зафиксированной верхней seq, запись `kind=gap`, если
  часть съедена кольцом; RAM — один кусок на клиента.

### zephyr-log-source
`LOG_BACKEND_DEFINE`, autostart; текст — `log_output_process()` в буфер 512 Б без
таймстемпа, уровня и источника; модуль — `log_source_name_get()`. Никаких `LOG_*`
внутри; потери — счётчик (`dropped` backend-а + отказы кольца). Ранние сообщения: кольцо
инициализируется до старта потока лога (`SYS_INIT` POST_KERNEL), а всё, что написано до
этого, лежит в deferred-буфере ядра лога и приходит в backend первым — отдельного
захвата не нужно; теряется только переполнение этого буфера (оно учитывается `dropped`).

### esp32-log-source
Ядро: байты → строки (512 Б + truncated, остаток строки отбрасывается), сброс частичной
строки по таймауту, CR/LF, ANSI CSI/ESC, недопустимый UTF-8 и управляющие байты → U+FFFD,
разбор `E/W/I/D/V (ms) tag: текст` (V → debug), иначе `unknown`. Адаптер: USART3
interrupt-driven (как `tty_serial` esp-serial-flasher в P6), в ISR — только FIFO → SPSC
`ring_buf`, счётчик переполнения; сборка строк на рабочем потоке coprocessor-manager.

### coprocessor-manager
Автомат `console ↔ usb_bridge ↔ flashing ↔ unavailable`, единственный владелец
IRQ-callback USART3 и линий EN/BOOT (после init драйвера ESP-Hosted). Переключение:
остановить RX текущего владельца, дождаться тишины ISR (таймаут → ошибка, режим не
меняется), отдать. `generation` растёт на сбросе C6 и возврате UART; маркеры `paused` и
`reset` в кольце ESP32. Взаимоисключение: `usb_bridge`/`flashing`/сброс ↔ сетевой apply
(transaction applying/awaiting/rolling_back); scan запрещён при `flashing`.

**`usb_bridge` — собственный passthrough** вместо узла `uart-bridge0`: узел выключается
в overlay приложения (дерево zephyr не правится). Причины: переключение — смена callback
без `CONFIG_PM_DEVICE`; один владелец callback с init; залипший USB-хост ведёт к отбросу
байтов со счётчиком, а не к остановке RX. Включение: команда шелла и DTR на CDC
(DTR=1 → мост, DTR=0 дольше порога → console).

### HTTP
`GET /logs/sources`, `/logs/records` (в буфере ответа, ограничение байтами),
`/logs/export` (поток кусками, `Content-Disposition`), `/coprocessor/status`.
`esp32_logs.available` = владение UART `console` и RX работает; `esp32_uart` —
`not_implemented` до P6; `transport_ready` — `net_adapter_wifi_present()`.

|---|---|
