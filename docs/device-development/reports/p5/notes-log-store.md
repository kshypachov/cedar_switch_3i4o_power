# P5 — заметки по log-store (fork A)

Записано по ходу реализации `modules/log-store` и `tests/log_store`.

## Решения реализации

| Вопрос | Решение | Почему |
|---|---|---|
| Раскладка записи | заголовок 28 Б (длина, level, флаги kind/has_module/truncated, длины module/text, source, generation, seq, uptime_ms) + module + text + выравнивание до 4 + хвост 4 Б (длина, magic `0xC3D5`) | хвост — обход назад для «последних `limit`» без индекса; magic отличает мусор при обходе назад |
| Размер записи | мин. 32 Б, макс. 608 Б | 28 + 64 + 512 → 604 + 4 |
| Модуль `NULL` и пустая строка | различаются флагом `has_module` | `module: null` у printk и маркеров, `""` — возможное имя |
| Lock | один `k_mutex` на оба кольца и seq; чтение — одна запись за удержание; счётчики потерь — отдельный `k_spinlock` | порядок фиксации = порядок seq; счётчик потерь вызывается из паникующего backend, где mutex нельзя |
| Потеря позиции при переполнении | позиция `< tail` → переносится на tail, `gap=true` | абсолютные позиции делают проверку арифметикой |
| Порядок проверок cursor | форма и контрольная сумма → дайджест фильтра (`-EINVAL`) → тег boot (`-ESTALE`) → позиция за head или не кратная 4 (`-EINVAL`) | cursor чужого boot с другими фильтрами — ошибка клиента, а не «новая загрузка» |
| Контрольная сумма cursor | FNV-1a 32 с фиксированной солью, не с ключом загрузки | ключ загрузки сделал бы cursor прошлого boot неотличимым от испорченного, а контракт различает их |
| Кодировка cursor | 29 Б → 39 символов base64url без `=`, только каноническая запись (неиспользуемые младшие биты = 0) | одна строка на одно значение |
| `strnlen` | собственный `bounded_len()` | хостовая libc sim-уровня с `-std=c17` его не объявляет (сборка упала) |
| `contains` | до 512 Б (128 кодовых точек по 4 Б), ASCII без учёта регистра | правка заголовка по запросу координатора; кириллица сравнивается побайтно |
| `sources == 0` | ничего не совпадает, reader стоит на обеих головах | правка заголовка по запросу координатора: фильтр `module` длиннее 64 Б |
| `reader.scanned` | обнуляется `reader_tail`/`reader_at`, копится `read` | правка заголовка: один бюджет на страницу из нескольких чтений |

## Семантика `gap` (найдено тестом)

`gap` — флаг reader-а: «с прошлого чтения что-то было перезаписано», не привязан к
конкретной записи. При `source=all` потеря в кольце STM32 обнаруживается при чтении,
которое может вернуть запись ESP32 со смежным seq, а пропуск номеров виден несколькими
записями позже. Первый вариант теста (`test_producer_during_reads`) сбрасывал флаг после
каждой записи и упал на размере 4 КиБ. Проверяемый инвариант: каждому пропуску seq
предшествует `gap`, выставленный после последнего `READ_END`. Для страницы это
соответствует контракту (флаг страницы); для экспорта запись `kind=gap` ставится при
первом замеченном флаге — до записи, после которой номера пропущены, а не точно на
месте пропуска.

## Измерено в sim

| Что | Результат |
|---|---|
| Типичные строки (модуль `net_dhcpv4`, текст 23–62 Б, в среднем 36) | измерено: 80 Б на запись, кольцо 4 КиБ — 51 запись; расчёт для 256 КиБ — ≈3 276 записей |
| Строка ROM C6 `invalid header: 0xffffffff` без модуля | расчёт по раскладке: 60 Б на запись, ≈4 369 в 256 КиБ |
| `test_producer_during_reads` | инвариант проверяется; сколько записей реально перезаписано между чтениями, в выводе twister не видно (журнал контейнера удаляется) — перекрытие чтения и записи не гарантировано планировщиком native_sim |
| Время удержания lock | на native_sim `k_cycle_get_32` грубый — 0 мкс; измерять на плате |
