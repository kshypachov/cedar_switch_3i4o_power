# system-image-store: notes

Fork A of the STM32 web update, 2026-09-15. Module `modules/system-image-store`,
tests `tests/system_image_store`, corpus `tests/fixtures/stm32`.

## Decisions taken in the fork

- **A module of its own, same API shape as firmware-store** (`sys_img_*` for
  `fw_store_*`, same errno table): firmware-store is file-centric and
  mutation-tested; the binding dispatches by target.
- **Metadata name `sysimg.meta`** in the same directory as firmware-store
  (`/lfs/firmware`): firmware-store removes names starting `upload`.
- **Id prefix `sysimg_`**: the binding can tell the two stores apart by id.
- **`slot_locked()` is checked by create and by chunk_accept** (right after the
  id lookup). A receiving upload cannot normally coexist with a locked slot, but
  a swap requested from the shell (`sysupd request`) could create one; refusing
  the chunk keeps revert material intact.
- **A `ready` upload is re-read from the slot at init** (SHA-256 TLV and image
  end). After an install's swap the slot holds the old image, so the upload
  disappears without the updater deleting it; after a revert it is `ready` again.
- **Sector repair and rollback**: a chunk starting mid-sector over bytes it cannot
  program rewrites the sector's accepted prefix. If the erase or the prefix
  rewrite fails, `received_bytes` drops to the sector start durably. Found while
  writing the failure test: without it a failed prefix write would have left
  erased bytes counted as received.
- **Vector check order**: magic → header size (target) → flags → sizes at the
  header; TLV structure → digest → vectors at the end. A damaged image reports
  `invalid_image` even if its vectors are also wrong.
- **Trailing bytes are refused.** A padded image (`imgtool --pad`) is refused as
  "continues too far past the image" - the firmware build does not pad.
- **`create` erases the trailer on the HTTP thread** (one 64 KiB erase on the
  SPI NOR, typically 0.15–1 s). Recorded as a cost for the binding.

## Corpus

15 files, 127 478 bytes, generated by imgtool 2.4.0 from the workspace; every
verdict agreed with the independent Python reading (`mcubootimage.py`) on the
first run.

## Found while testing

- **Lost prefix on a failed repair** (above): fixed; `received_bytes` drops to the
  sector start, recorded when possible and always in RAM.
- **`fs_unlink()` logs `failed to unlink path (-2)` for a missing file** (known from
  P6, memory `littlefs-statvfs-full-traversal`): the store looks with `fs_stat()`
  before unlinking; the suite's log has no such line.
- `delete` succeeds with a leftover `sysimg.meta.tmp` it cannot remove (a
  non-empty directory in the test); it fails `-EIO` only when the record itself
  cannot be removed.

`mcuboot_image.c`/`.h`, 111 on `system_image_store.c`). Round 4, the first valid one
(baseline passing before and after): **136 killed, 23 survived, 2 unusable

Equivalent survivors, not closed:

| Mutant | Why equivalent |
|---|---|
| M27 | a partial entry header at the end of the TLV area: when `p + 4 > end`, the next check `p + 4 + len > end` fails too, with the same message |
| M32 | dropping `end != 0` from the RAM range test: an unused range (0, 0] contains no stack pointer anyway |
| M41 | dropping `!image_hashed`: it is false only when the file was not fed whole (already failed) or PSA's finish failed, which the sim cannot inject |
| M44 | `fail()` overwriting the first verdict: every call site is already guarded by `result == OK` (check_header returns after its first failure, the end checks are gated) |
| M46 | not clearing `hashing` in abort: `psa_hash_abort()` on an aborted operation is a no-op |
| M48 | dropping `result == OK` from the feed's capture gate: `header_ok` is set only by a header check that did not fail, and nothing fails between the header and the end |
| S17 | no `fs_sync()` before close: `fs_close()` syncs in LittleFS; only a power cut between the two would show it |
| S32 | dropping `sector > 0`: a zero sector fails `trailer_bytes % sector == 0` (division by zero returns 0 on AArch64 and Cortex-M without the trap), so it is still refused |
| S47 | dropping `state == READY` from `has_image`: `has_image` is 1 only in a `ready` record, and a `ready` upload cannot be checked again |
| S68 | the head check reading at `offset` instead of `offset + done`: the head is shorter than a sector, and the read buffer is a sector, so the loop runs once |
| S107 | dropping `verifying` and `has_image` from `image_info`'s check: a `ready` upload cannot be `verifying`, and a `ready` record always has an image |

## Harness trap: native_sim's flash file lands in the workspace root

`cedar-sim-tests:1` has `WORKDIR /ws`, and native_sim's flash simulator maps
`./flash.bin` unless given `--flash=`. A test binary run directly with
`docker exec` (not through twister, which runs it in its build directory)
therefore maps `/Volumes/Programming/Zephyr/zephyr_latest/flash.bin` - the host
workspace root, shared by every sim run started that way. The file existed before
this fork's runs; it was written by them (mtime 18:02) and is left in place - it
holds only sim flash contents.

The runner now passes `--flash=/mut/flash-forkA.bin --flash_rm` with `/mut` as the
working directory. This was suspected, not shown, to be why the first rounds
failed; the cause is below.

## Harness trap: restored sources keep old mtimes

The first three mutation rounds were discarded. Round 1 reported 96 of 129 mutants
failing at `store.c:236`, including mutants that cannot reach that path; rounds 2
and 3 failed their own pristine baseline at lines 236 and 926. Both lines test the
recovery re-read of a `ready` upload, which mutant S25 disables.

Cause: restoring the container's copy of the sources with `shutil.copytree` (first
runner) or `cp -a` keeps the host files' modification times, older than the
objects a mutant had just compiled. Ninja does not rebuild, and every later run,
the "pristine" baseline included, links the stale mutated object. It was made worse
by a round stopped with `pkill` while S25 was written in. The host worktree was
never touched.

The runner now: restores the copy from the worktree when they differ, **touches
every source**, runs the baseline and stops if it fails, and writes each mutant
back in a `finally`. Discarded logs: `round1-shared-flash-discarded.log`,
`round2-leftover-mutant-discarded.log`, `round3` (baseline stop) in the fork's
scratchpad.
