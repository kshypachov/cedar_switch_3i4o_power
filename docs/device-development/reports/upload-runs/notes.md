# Загрузки прошивки STM32 через API: сравнение (2026-09-19)

Задачи владельца (02:5x): 1) догрузить 7ddc4847 и перезапуститься; 2) подтвердить через
telnet; 3) залить `build/…/zephyr.signed.bin` уже через новую прошивку; 4) сравнить;
5) подтвердить; 6) переписать запись слота 2 на `stream_flash`; 7) залить прошивку со
`stream_flash`; 8) подтвердить; 9) залить её ещё раз, проверить надёжность.
Исследование медленной загрузки — только после 1–9.

Плата 192.168.88.10 (Wi-Fi), клиент — скрипт `web_update_a.py` (копия в scratchpad:
`CHUNK_BYTES`, `CHUNK_DELAY`, докачка с `received_bytes`, ожидание куска до 600 с).
Параметры для сравнения (решение владельца): куски 4096 Б, пауза 1 с после куска.
«Прерывание» — зависание платы, сброс IWDG (`reset cause 0x11`), кроме отмеченных.
Поправка (позже 2026-09-19): coredump в этих прошивках не писался вообще (две ошибки,
`reports/coredump`, «Проверка на плате»), поэтому «нет дампа» не отличает зависание от
падения — «зависание» ниже значит только «сброс по IWDG».
