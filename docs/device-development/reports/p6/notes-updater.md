# P6 — esp-loader-adapter и coprocessor-updater (форк B)

Модули: `modules/esp-loader-adapter`, `modules/coprocessor-updater`; тесты
`tests/esp_loader_adapter`, `tests/coprocessor_updater`; фейки `tests/fakes/fake_esp_loader.*`,
`tests/fakes/fake_update_platform.*`. Решения и отказы — в README модулей.

## Что добавлено вне двух модулей

- **job-manager: `job_set_cancellable(id, bool)`** — задача обновления отменяема до `begin` и
  перестаёт быть отменяемой на `begin`. Без атомарной смены под lock менеджера отмена,
  пришедшая в момент перехода, переводила бы задачу в `cancelled`, пока ROM уже стирает.
  Возвращает `-EINVAL`, если задача уже терминальна (отмена успела) — updater так и узнаёт об
  отмене. Тест `test_set_cancellable_closes_the_window_and_reports_a_cancel` (job_manager 23 → 24).

## Находки при разработке

- **Опасность порта tty (с платы B, сообщение родителя).** `esp_loader_init_serial()` ставит
  обработчик tty на USART3 с включённым приёмом; при переполнении кольца 512 Б
  `uart_rx_handle()` пишет `~` на каждый потерянный байт из ISR с `K_FOREVER` в кольцо передачи,
  которое никто не опустошает. ROM-флуд непрошитого C6 вешал плату B на старте. Адаптер: порт
  инициализируется только в `open()` после перехода менеджера в `flashing`, прямо перед connect;
  любой отказ библиотеки в `open/begin/write/finish` снимает сессию целиком до возврата. Тест
  `test_no_failure_leaves_the_port_initialised` проходит все точки отказа.
- **`zephyr,deferred-init` на узле `esp_loader0` (решение родителя).** Устройство библиотеки не
  инициализируется ядром, `device_is_ready()` ложно всегда, `device_init()` не вызывается. Порт в
  `zephyr_port.h` не экспортирован: это первый член данных устройства (`struct esp_loader_dev_data
  { zephyr_port_t interface; esp_loader_t loader; }`, `port/zephyr_port.c:25`). Таблица над
  библиотекой берёт его оттуда и сверяет `interface.config` с `esp_loader_config_from_device()`;
  при несовпадении `port_init` отказывает. Библиотека не правилась.
- `esp_loader_flash_write()` не дополняет последний блок (`FLASH_DATA` уходит с фактическим
  размером, MD5 считается по нему), а `flash_start` требует размер, кратный 4 — адаптер
  дополняет образ `0xFF` до кратного 4 сам (`BUILD_ASSERT` блок кратен 4).
- Kconfig: `$(dt_chosen_enabled,zephyr,esp-loader)` разбирается как два аргумента — нужна
  переменная `DT_CHOSEN_ZEPHYR_ESP_LOADER := zephyr,esp-loader`.

## Мутации

Копия модулей и тестов в scratchpad, внутри отдельного контейнера (`docker cp`), по одному
мутанту: пересборка `native_sim/native/64` и прогон набора; для адаптера — обе конфигурации.
Операторы: сравнения, `&&`/`||`, `true`/`false`, `!`, `+`/`-`, `return 0`/`return rc`, `break`,
`goto`, `0U`/`1U`, удаление вызова. Мутант, повесивший набор, считается убитым.

| Файл | Мутантов | Первый проход: убито / выжило / не собралось | После новых тестов: убито / выжило |
|---|---:|---|---|
| `esp_loader_adapter.c` | 140 | 112 / 27 / 1 | 133 / 6 (21 убиты новыми тестами) |
| `esp_loader_adapter_updater.c` | 20 | 10 / 10 / 0 | 15 / 5 |
| `coprocessor_updater.c` | 246 | 187 / 58 / 1 | 226 / 19 (39 убиты новыми тестами) |

Тесты, добавленные по выжившим: каждый указатель платформы/таблицы по отдельности `NULL`;
retryable и code у каждого отказа; порт прошлой сессии не трогается; первая ошибка close
сохраняется; итог `interrupted` не наследует версию и флаги прежнего; граница `last.phase ==
COUNT`; длины всех строк журнала и соседние поля; повторный `run()` ничего не делает; самый
длинный upload id доходит до образа целиком; чтение за концом образа; чтение, вернувшее 0 байт;
прогресс в байтах до первого блока; отмена между `running` и проверкой preflight (hook на
сохранение журнала); сохранения журнала при отмене в очереди; блокировка мьютекса не остаётся
после каждого публичного вызова (второй поток читает состояние); ошибки write/finish и
неизменная ошибка при успехе в ops для updater.

Выжившие, обоснованно (30):
- **Удаление `k_mutex_lock` (updater, 8)** — мьютекс защищает только копии от параллельного
  читателя; в sim гонку не воспроизвести, а удаление `unlock` убивается тестом второго потока.
  `unlock` в ветке `-EBUSY` внутри `start` (1) недостижим: `check()` отказывает раньше.
- **Размеры буферов на 2 меньше** (`timeout_message`, `run.job_id`, `app_version`, 3) —
  реальные строки короче: сообщение о таймауте ≈45 символов из 127, id задачи `job_%08x` —
  12 из 31, версия из консоли только логируется.
- **Терминаторы строк** (`strncpy` с `cap - 0U`, `upload_id[sizeof + 1]`, `version[sizeof ± 1]`, 4) —
  результат тот же: `copy_str` сам ставит терминатор; лишний байт уходит в выравнивание структуры
  или в поле, которое на этом пути и так `false`; платформа по контракту возвращает строку с
  терминатором.
- **Только журнал** (`if (rc != 0)` перед `LOG_ERR` в `save`, `if (first != 0)` перед `LOG_ERR`, 2),
  **`memset(&j)` перед загрузкой** (1, перезаписывается в ветке отказа), **`session = true` перед
  teardown** (1, teardown сам сбрасывает), **`&&`→`||` у первой ошибки в `lines_idle`** (1, `first`
  там всегда 0), **удаление `BUILD_ASSERT`** (1, проверка времени сборки), **`ARG_UNUSED` в ops**
  (5, макрос без кода).
- **`open()` до `esp_loader_adapter_init()`** (2, текст и retryable ошибки `-EAGAIN`) — в одном
  бинарнике тестов после первой инициализации недостижимо: сбросить указатель на таблицу нечем.
- `job_set_cancellable` в job-manager мутациями не прогонялся (5 строк, покрыт тестом job_manager
  и тестами отмены updater).
- Сборка для платы (scratchpad `forkB-zcheck`, overlay `esp_loader_integration` + `zephyr,deferred-init`,
  `CONFIG_ESP_LOADER_ADAPTER_ZEPHYR` и `UPDATER_OPS`): без ошибок и предупреждений — настоящая
  таблица над `esp_loader_*` компилируется. На плате не запускалась.
