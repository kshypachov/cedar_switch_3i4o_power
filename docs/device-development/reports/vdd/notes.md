# Напряжение питания VDD (2026-09-19)

Задача владельца: «подозреваю, что перезагрузки платы связаны с питанием, я установил
конденсаторы с низким ESR в цепь LDO… добавь отдельную задачу, которая по запросу
будет делать 1000 измерений внутреннего напряжения питания… самое низкое, самое
высокое, среднее и медианное… Залей на обе платы, измерь в покое и при заливке прошивки».

## Как измеряется

- Шелл: `vdd [count] [period_us]`, по умолчанию 1000 измерений через 10 мс (окно ~11 с).
  Решения владельца: только шелл; VDDA на этой плате — прямо VDD (выход LDO).
- Поток `vdd_monitor` (приоритет 3) спит между измерениями; шелл ждёт итог.
  Тик ОС — 100 мкс (`SYS_CLOCK_TICKS_PER_SEC=10000`), а не 10 мс; `k_yield()` сам не
  ждёт, поэтому интервал задаётся явно.
- Измерение: VREFINT через ADC1 и заводскую калибровку, драйвер Zephyr `stm32_vref`
  (`&adc1`, `&vref1` в overlay, ADC 40 МГц = HCLK/4). Результат — VREF+ = VDDA.
- Вывод: min, max, среднее, медиана (мВ), реальное окно, самый длинный промежуток
  между измерениями, когда был минимум.
- Код: src/diagnostic/vdd_monitor.c. Та же прошивка 1.1.2 добавила мигание LED на PC2
  (src/io/status_led.c, задача 3 владельца).

## Что говорит история сбросов

Все сбросы `.10` во время загрузок — `reset cause 0x11` = pin + watchdog, ни одного
`brownout`: декодер (`system_service.c`, `hwinfo_stm32.c`) видит `RCC_CSR.BORRSTF`.
Значит, провала до сброса по BOR (порог BOR по умолчанию ~1,7 В) не было. Не исключено
более мелкое проседание ниже минимума внешних памятей (OSPI NOR, PSRAM — от 2,7 В),
которое портит выборку кода → падение → IWDG. Предел инструмента: одно преобразование
~20 мкс раз в 10–40 мс — это ловит просадку LDO, но не микросекундные выбросы. Для них —
PVD (прерывание по порогу) или осциллограф.
