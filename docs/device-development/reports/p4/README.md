# Отчёт этапа P4 — сеть

Критерий раздела 10: «Все сценарии apply/confirm/timeout/power-loss, достижимость
Matter при Wi-Fi-only». Раздел 12 добавляет к `network-manager` аппаратные строки:
DHCP и static на W5500 и C6, снятие кабеля, scan, reconnect, два интерфейса в
одной подсети.

**Статус: не закрыт.** Всё программное и все сценарии на плате B выполнены, включая
снятие кабеля и потерю питания в `awaiting_confirmation`; пять циклов питания заменены
сбросом через J-Link. Открыты:
- строки Wi-Fi и Matter при Wi-Fi-only, по решению владельца — до P6;
- пункты раздела «Не сделано и открыто».

Работа велась в отдельном worktree `zephyr_latest/cedar_p4`, ветка `p4-network` от
`0cb7f60`; коммитов нет. Аппаратные проверки — только на плате B (J-Link); плату A
(ST-Link, сессия P3) не прошивали, не сбрасывали, запросов ей не слали.

Каждая запись или стирание слота — 512 байт значения BYTES (фиксированный размер
реестра), в файле — строка base64 ≈700 символов; стадия, apply и commit пишут по
несколько строк, файл уплотняется при 128 строках. Пока идёт запись журнала,
кооперативный HTTP-сервер стоит: в последнем прогоне новый адрес ответил через 32 с
после apply.

## Найдено и исправлено в P4 на плате

1. **Переполнение стека `main`** (образ 1): загрузка хранилища на 2 КиБ стека. Старт
   сервиса перенесён на его рабочую очередь; `prj.conf` не менялся.
2. **Ручной DNS не удалялся** (образ 2): `dns_resolve_remove_server_addresses()` без
   интерфейсов не находит ни одного сервера (`idx_of_server_addr()` пропускает все слоты
   при `if_index == 0`), а у ручного сервера интерфейса нет. Адаптер закрывает контекст
   резолвера. Кандидат на issue в Zephyr.
3. **Патч W5500 v1 ломал приём** (образ 2): сдвиг `Sn_RX_RD` на `Sn_RX_RSR`, прочитанный
   как 65535, уводил указатель; после сброса плата не принимала ничего. v2/v3
   переоткрывают сокет 0.
