# HLW8032 + энергия в FRAM: план (2026-09-19)

## Задача владельца

Отдельный модуль для HLW8032 (USART2, только RX на PA3): приём полной посылки по
прерыванию, проверка контрольной суммы, разбор, структура с текущими данными.
Накопленная энергия переживает перезагрузки и внезапное пропадание питания — в FRAM,
штатным механизмом: **отдельный экземпляр ZMS**, в FRAM **только энергия**, settings
остаются на NOR. Коэффициенты подстройки напряжения, тока и энергии меняются во время
работы. Энергия сохраняется раз в секунду; UART и FRAM не заставляют ждать другие
потоки. **Приоритет — компактность и простота кода.** FRAM и HLW8032 есть только на
плате 192.168.88.10; всё проверяется там по сети.

## Факты, на которых стоит план

- HLW8032 (даташит REV 1.5): 4800 8E1, посылка 24 байта (24 × 11 бит = 55 мс), затем
  пауза ~50 мс (уточнил владелец; сначала здесь стояло «посылки вплотную»).
  Байт 0 — State: 0x55 норма, 0xAA — коэффициенты чипа неисправны (посылку отбросить),
  0xFx — бит 3/2/1 = переполнение регистра напряжения/тока/мощности (величина ≈ 0),
  бит 0 = коэффициенты неисправны. Байт 1 = 0x5A. Байт 20: биты 6/5/4 — регистры
  напряжения/тока/мощности обновлены, бит 7 переключается при переполнении PF.
  Байты 21–22 — PF (16 бит), байт 23 — сумма байтов 2..22.
- Типовая схема даташита = старый проект: делитель 4 × 470 кОм / 1 кОм (VF = 1,88),
  шунт 1 мОм (CF = 1). Импульсов на 1 кВт·ч = 10⁹ · 3600 / (PowerPar · VF · CF).
- DT платы: `&usart2` только `usart2_rx_pa3`, 4800, **без `parity`** (8N1) — нужно even.
- В Zephyr нет flash-драйвера для FRAM; ZMS работает только через flash API и
  поддерживает память без стирания (`caps.no_explicit_erase`).
- SPI1 с DMA при DCACHE принимает буферы только в SRAM; драйвер FRAM кладёт байты
  команды на стек вызывающего потока. `.bss` библиотеки `app` уходит в PSRAM.

## Решение

Новый модуль `modules/energy-meter/` (своя библиотека `energy_meter`, как
`flash-sram-proxy`: `zephyr/module.yml`, `Kconfig`, `CMakeLists.txt`, `dts/bindings`).

1. **`src/eeprom_flash.c`** — `cedar,eeprom-flash`: flash API поверх EEPROM-устройства
   (`eeprom = <&fram0>`), ~80 строк, без своего потока. read/write → `eeprom_read/write`,
   erase → `flash_fill(dev, 0xFF, …)`, параметры
   `write_block_size = 1`, `erase_value = 0xFF`, `caps.no_explicit_erase = true`,
   `page_layout` = одна страница на всё устройство, размер — `size` узла EEPROM.
   Kconfig: `select FLASH_HAS_DRIVER_ENABLED`, `FLASH_HAS_NO_EXPLICIT_ERASE`,
   `FLASH_HAS_PAGE_LAYOUT`. Вызывать только с потока со стеком в SRAM (контракт,
   комментарий; вызывающий один — очередь модуля).
2. **`src/hlw8032.c/.h`** — чистые функции без Zephyr: `hlw8032_frame_ok(buf)` (байт 1 = 0x5A,
   сумма, State = 0x55 или 0xF0–0xFF без бита 0; 0xAA и всё прочее — не посылка — это же
   защищает скользящее окно от ложной синхронизации) и `hlw8032_parse(buf, &regs)` (параметры и
   регистры, флаги обновления/переполнения, PF). ~60 строк; юнит-тест на native_sim
   (`tests/energy_meter`, как остальные модули): правильная посылка, плохая сумма,
   0xAA, переполнения, приращение PF через переход 0xFFFF→0.
3. **`src/energy_meter.c`** — ~200 строк:
   - **Одна выделенная очередь работ** (`k_work_queue`, стек `K_THREAD_STACK_DEFINE` —
     `.noinit`, остаётся в SRAM). Все обращения к ZMS/FRAM — только в ней; это и есть
     «ZMS выполняет всё из своей очереди»: у самого ZMS потока нет, он работает в
     потоке вызывающего под своим мьютексом.
   - **UART**: асинхронный API с DMA (GPDMA1, свободный канал, запрос 26 USART2_RX,
     только `dma-names = "rx"`), два буфера по 24 байта (`__noinit` → SRAM: обычный `static` попал бы в PSRAM и DMA
     писал бы мимо кеша), таймаут `SYS_FOREVER_US` — одно событие на 24 байта,
     `RX_BUF_REQUEST` → `uart_rx_buf_rsp`, `RX_DISABLED` → снова `uart_rx_enable`.
     Колбэк (прерывание DMA) сдвигает байты в 24-байтовое окно и, когда
     `hlw8032_frame_ok()`, копирует посылку под спинлоком и ставит работу в очередь.
     Одно прерывание на 24 байта; процессор не ждёт.
   - **Работа «посылка»**: разбор, V/I/P/PF с коэффициентами, приращение импульсов
     `(pf - last_pf) & 0xFFFF` (первая посылка после старта только задаёт `last_pf`;
     `last_pf` не сохраняется — чип после сброса питания начинает PF с 0).
   - **Работа «секунда»** (`k_work_delayable`): если счётчик импульсов изменился —
     `zms_write(id 1, uint64)` (8 байт — данные внутри одной ATE, атомарно, с CRC);
     публикация в существующий канал zbus `energy_mon_topic` (в `enegry_mon_t`
     добавить `power`; `frequency` остаётся 0 — HLW8032 её не даёт).
   - **ZMS**: `struct zms_fs` (с кешем поиска 2048 × 8 = 16 КБ, опция общая с settings)
     в `.bss` → PSRAM строкой `*libenergy_meter.a:*(.bss .bss.* COMMON)` в
     `psram_sections.ld`; к ней обращается только CPU. Раздел `energy` на все 8 КБ,
     4 сектора по 2 КБ. Монтирование в очереди: `zms_mount`; `zms_mount_force` только при
     `-ENOTSUP` (раздел не ZMS), при -EIO/-ENXIO — лог и повтор, счётчик не трогать.
     В `zms_write` — копия значения на стеке очереди (SRAM). Стек очереди 2 КБ.
     ZMS, а не LittleFS: одна атомарная запись 16 байт на сохранение против коммита из
     нескольких блоков и ~1 КБ кешей.
   - **Хранится сырое значение** — число импульсов PF (uint64). Энергия =
     импульсы / импульсов_на_кВт·ч × k_energy: коэффициент энергии применяется при
     чтении и пересчитывает всю историю.
   - **Коэффициенты**: три ключа `settings-registry` (`energy/cal/voltage`, `/current`,
     `/energy`, F32, по умолчанию 1.0, допустимо 0.5–2.0; `CONFIG_SETTINGS_REGISTRY_F32=y`)
     — на NOR, как все настройки. Читаются в работе «посылка» через `setting_get()`.
   - **API**: `energy_meter_get(struct energy_reading *)` (копия под спинлоком),
     `energy_meter_start()` из `main.c`. Номиналы (делитель, шунт) — Kconfig, по умолчанию
     из даташита (1,88 МОм / 1 кОм, 1 мОм): владелец не подтвердил номиналы этой платы. **Шелл**: `energy` (показания, импульсы,
     сохранённое значение, счётчики посылок/ошибок), `energy cal v|i|e <k>`,
     `energy reset` (обнуление через очередь).
4. **Оверлей**: `&usart2 { parity = "even"; dmas = …; dma-names = "rx"; }`, узел
   `fram_flash: fram-flash { compatible = "cedar,eeprom-flash"; eeprom = <&fram0>;
   partitions { energy_partition: partition@0 { label = "energy"; reg = <0 0x2000>; }; }; }`.
5. **Старый `src/energy_monitoring/`** — убрать из `CMakeLists.txt` и из `main.c`
   (include и закомментированный вызов); файлы не удалять без разрешения владельца.

## Не сломать существующие settings

- `select FLASH_HAS_NO_EXPLICIT_ERASE` делает `flash_params_get_erase_cap()` проверкой
  `caps.no_explicit_erase` во время работы для всех устройств. У `spi_nor.c:301`,
  `flash_stm32_ospi.c:1761`, `flash_stm32.c:43` поле `caps` не задано → 0 → стирание
  остаётся явным; `nor_proxy` отдаёт параметры `spi_nor`. ZMS (`zms.c:437/1315/1658`),
  LittleFS (`littlefs_fs.c:655`), `flash_flatten()` решают по устройству.
- `CONFIG_ZMS_LOOKUP_CACHE_FOR_SETTINGS` — только функция раскладки кеша (хеш под ID
  settings); для второго экземпляра с ID 1 корректность не страдает, кеш просто
  неоптимален. `ZMS_LOOKUP_CACHE_MANUAL` не берём: `settings_zms.c` его не поддерживает,
  settings остались бы без кеша.
- Settings выбирают раздел через `chosen zephyr,settings-partition = &storage_zms_partition`;
  в коде разделы берутся по метке (`FIXED_PARTITION_ID(...)`), числовых ID нет.
- MCUboot собирается без оверлея приложения — не затронут.
- На плате: вход в веб (пароль из settings), запись и чтение настройки, перезагрузка,
  `flash erase` + чтение на разделе scratch NOR (должно дать 0xFF), Matter-фабрики на месте.

## Проверка на .10 (по сети)

VERSION 1.1.3+18, загрузка через веб (куски 16 КБ без пауз), установка, telnet:
лог монтирования ZMS; `energy` — посылки идут, ошибок суммы нет, напряжение ≈ сети;
`energy cal` меняет показания; счётчик импульсов растёт под нагрузкой; перезагрузка —
энергия на месте; проверки settings выше; `sysupd confirm` в течение 20 мин;
сверка ∫P·dt за ~60 с под постоянной нагрузкой с приращением энергии по импульсам
(проверка константы 3,6·10¹²). Результаты — `reports/energy/notes.md`.

Ревью советчика 2026-09-19: учтены правило State, force только при -ENOTSUP, `__noinit`
для буферов DMA (проверка по `zephyr.map`), `flash_fill` для erase, номиналы в Kconfig.

**Изменено по решениям владельца после первой проверки** (подробно — `notes.md`):
синхронизация по паузе (прерывание IDLE, `timeout = 0`) вместо скользящего окна; в FRAM
хранится энергия в мкВт·ч (ZMS id 2), коэффициенты применяются к новым порциям, а не
при чтении. Публикация в zbus не сделана — потребителей канала пока нет.
