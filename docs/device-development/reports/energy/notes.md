# HLW8032 + энергия в FRAM: заметки (2026-09-19)

План и решения — `plan.md`. Здесь — протокол по даташиту и результаты.

## Протокол HLW8032 (даташит REV 1.5, стр. 10–17)

Источник: HLW8032 User manual REV 1.5 (hiliwi.com; копия LCSC C128023). Формулы в PDF
нарисованы векторно и в текст не извлекаются — прочитаны по отрисованным страницам.

**UART (стр. 10).** Только передача от чипа (TX → MCU); RX чипа «reserved», не используется.
4800 бит/с, старт + 8 бит данных (младший бит первым) + бит чётности **even** + стоп
(8E1). Посылка — 24 байта, «interval for transmitting data is 50 ms». При 8E1 байт — 11 бит,
посылка длится 24 × 11 / 4800 = 55 мс. По словам владельца и по плате (≈ 9,5 посылки в с)
50 мс — это пауза между посылками, период ≈ 105 мс; синхронизация — по паузе (ниже).

**Регистры, по порядку передачи (стр. 11):**

| байт | регистр | длина | что |
|---|---|---|---|
| 0 | State REG | 1 | состояние |
| 1 | Check REG | 1 | всегда 0x5A |
| 2–4 | Voltage Parameter REG | 3 | «default» — калибровка чипа |
| 5–7 | Voltage REG | 3 | |
| 8–10 | Current Parameter REG | 3 | «default» |
| 11–13 | Current REG | 3 | |
| 14–16 | Power Parameter REG | 3 | «default» |
| 17–19 | Power REG | 3 | |
| 20 | Data Updata REG | 1 | флаги обновления |
| 21–22 | PF REG | 2 | счётчик импульсов PF; **не сохраняется при пропадании питания** |
| 23 | CheckSum REG | 1 | сумма |

24-битные регистры и PF передаются старшим байтом вперёд (стр. 12–14).

**State REG (стр. 12).** Биты 7–4 — резерв (1). Бит 3/2/1 — переполнился регистр
напряжения/тока/мощности; бит 0 — регистры параметров непригодны. Толкование в тексте:
0xAA — коррекция ошибок чипа не работает, параметры непригодны; 0x55 — норма, переполнений
нет; 0xFx — параметры пригодны, установленный бит = регистр переполнился, «величина очень
мала и близка к 0».

**Data Updata REG (стр. 13–14).** Бит 7 — инвертируется при каждом переполнении PF (PF
при этом обнуляется); бит 6/5/4 — обновление регистра напряжения/тока/мощности
завершено (0 — ещё не завершено); биты 3–0 — резерв. Пункт «3、When bit4 = 1,» в даташите
оборван — продолжения нет.

**CheckSum (стр. 14).** Младшие 8 бит суммы всех регистров, кроме State, Check и самого
CheckSum (байты 2..22). При несовпадении посылку отбросить.

**Формулы (стр. 15–17):**
- U = Voltage Parameter REG / Voltage REG × Kv; Kv — коэффициент делителя: 4 × 470 кОм /
  (1 кОм × 1000) = 1,88.
- I = Current Parameter REG / Current REG × Ki; Ki = 1 / (R × 1000), R шунта в омах;
  0,001 Ом → 1.
- P = Power Parameter REG / Power REG × Kv × Ki; S = U × I; PF = P / S.
- Импульсы: PFcnt = k × 65536 + n (k — сколько раз инвертировался бит 7, n — PF REG).
- Импульсов на 1 кВт·ч = 1 / Power Parameter REG × 1 / (Kv × Ki) × 10⁹ × 3600;
  энергия, кВт·ч = PFcnt / (импульсов на 1 кВт·ч).

## Сверка с кодом (`modules/energy-meter/src`)

| даташит | код |
|---|---|
| 8E1, 4800, только приём | оверлей `&usart2 { parity = "even"; }`, pinctrl только PA3 |
| байт 1 = 0x5A; сумма 2..22 | `hlw8032_frame_ok()` |
| 0x55 норма; 0xAA — отбросить; 0xFx, бит 0 — отбросить | `f[0] == 0x55 \|\| (f[0] & 0xF1) == 0xF0` |
| 0xFx биты 3/2/1 — величина ≈ 0 | `hlw8032_parse()`: регистр = 0 → U/I/P = 0 |
| бит 6/5/4 = 0 — не обновлён | регистр сохраняет прошлое значение |
| формулы U, I, P, S, PF | `frame_handler()`, Kv = DIVIDER/1000, Ki = 1000/SHUNT_UOHM (мкОм) |
| PFcnt = k × 65536 + n | приращение `(uint16_t)(pf − last_pf)` за посылку — то же самое, пока между двумя принятыми посылками меньше 65536 импульсов (при P_par ≈ 5·10⁶ и 3,5 кВт — ≈ 176 с без посылок); бит 7 не нужен |
| PF не сохраняется при пропадании питания | база `last_pf` не хранится, первая посылка после старта только её задаёт |
| импульсов на кВт·ч | каждая посылка добавляет `новые импульсы × P_par × Kv × Ki × k_e / 3600` мкВт·ч (см. ниже) |

Расхождений с даташитом не найдено.

## Изменения после первой проверки (решения владельца, 2026-09-19)

- **Синхронизация по паузе.** Владелец: между концом одной посылки и началом следующей
  пауза ~50 мс (то есть «interval 50 ms» в даташите — это пауза, период ≈ 105 мс).
  `uart_rx_enable(..., 0)`: драйвер `uart_stm32` сообщает принятые байты из аппаратного
  прерывания IDLE (линия молчит один символ, `uart_stm32.c:1501`). Событие по неполному
  буферу — пауза: окно очищается, следующая посылка всегда начинается с нулевого байта.
  Скользящий сдвиг окна убран.
- **В FRAM — энергия, а не импульсы.** Владелец: коэффициент не должен пересчитывать
  уже накопленное. В электронных счётчиках накопленная энергия — отдельный регистр в
  физических единицах, калибровка хранится отдельно и влияет только на новую энергию;
  сохранение — периодически и по сигналу о пропадании питания. Теперь каждая посылка
  добавляет `новые импульсы × P_par × Kv × Ki × k_e / 3600` мкВт·ч с коэффициентами этого
  момента; хранится `uint64` мкВт·ч (ZMS id 2; id 1 с импульсами из 1.1.3+18 не читается),
  дробная часть мкВт·ч — только в RAM. Импульсы — счётчик с момента загрузки, для
  диагностики.

## Проверка на 192.168.88.10

**1.1.3+18** (`7444eb2e`, импульсы в FRAM, синхронизация по содержимому), 2026-09-19 19:54:
посылок 9,4 в с; 233 В; пропущено 9–14 байт только при первой синхронизации; ошибок
UART 0; ZMS на FRAM (прежде заполненной нулями) смонтировался сам, без предупреждения;
после `kernel reboot cold` счётчик поднялся с сохранённого значения (37 → при старте 38).

**1.1.3+19** (`076e9daf`, синхронизация по паузе, энергия в мкВт·ч), 20:14–20:17:

| проверка | результат |
|---|---|
| посылки | 9,7 в с (178 → 304 за 13 с), отброшено 0 байт, ошибок UART 0 |
| показания | ~232 В, ~2 Вт (нагрузка платы), счёт идёт |
| коэффициент энергии 1,0 → 2,0 → 1,0 | ≈ 2,7 → ≈ 5,4 мВт·ч на импульс; после возврата к 1,0 накопленное не уменьшилось (54 → 59 мВт·ч) |
| перезагрузка | до неё 84 мВт·ч, после старта `energy counter: 86329 uWh`, счёт продолжается |
| settings | вход в веб по паролю; Matter ready, те же 3 fabric; сеть revision 1, тот же SSID — как до прошивки 1.1.3+18 |
| образ | подтверждён `sysupd confirm` |
| коэффициенты в settings | `energy cal e 1.1`, перезагрузка → `energy 1100 (x1000)`; возвращено 1.0 |

Не проверено: внезапное пропадание питания (не программная перезагрузка); сверка
∫P·dt с приращением энергии под постоянной нагрузкой; номиналы делителя и шунта этой
платы (стоят значения типовой схемы даташита).

Известный крайний случай: пока ZMS на FRAM не смонтирован (монтирование повторяется
раз в секунду), импульсы продвигают базу PF, но энергия не копится — эти импульсы
теряются. На плате FRAM монтировался при каждом старте. Исправление — копить всегда и
при монтировании прибавлять сохранённое значение — меняет поведение, решает владелец.
