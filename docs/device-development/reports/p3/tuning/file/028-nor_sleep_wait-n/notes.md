SPI_NOR_SLEEP_WHILE_WAITING_UNTIL_READY=n: по правилу «лучше» (51,70 с, −1,61), и выигрыш не только в медианах — каждый цикл на 2–4 % быстрее базы: старт с fabric среднее/макс 20,5/47,3 с (база 21,0/48,2), удаление 28,8/59,5 (29,6/60,8), commit 1,6–3,2 (1,8–3,3); стирание раздела 14,2 с (16). bench 290 мс (310–317) — чтение ожиданий не содержит, разницу не объясняю.

Механизм по spi_nor.c: после записи страницы драйвер опрашивает WIP и со сном засыпает на WAIT_READY_WRITE = K_TICKS(1) (0,1 мс при 10000 тиков/с) + переключение контекста; без сна опрашивает подряд. File пишет много (дописывание, сжатие) — выигрыш есть; у ZMS записей мало — шум (027 zms). Цена: пишущий поток занимает процессор всё ожидание (на стирании блока — десятки мс), обратное эффекту прерываний SPI. Малый выигрыш; в file-comboA не взят (цепочка уже собирает read-size 32 + interrupt), кандидат для отдельной проверки вместе с interrupt.
