Объяснение по коду (гипотеза, не мерил осциллографом): LittleFS заполняет кеш чтения не на cache_size, а до `lfs_alignup(off+hint, read_size)` (lfs.c:114, 842). С read-size 32 каждое мелкое чтение метаданных — отдельная короткая SPI-транзакция. В режиме опроса короткая транзакция дешёвая, поэтому read-size 32 ускорял. С прерываниями у каждой транзакции постоянная цена: прерывания на байт, ожидание завершения, переключение потоков. Число транзакций растёт в разы, и эта цена съедает выигрыш прерываний. read-size 32 полезен только без прерываний, interrupt — только с крупными чтениями.

Решение: comboA не итог. Подтверждение на 10 циклах (034) снято; 033 (повтор на 5 циклах) доработала как проверка. Дальше: comboB = interrupt + SPI_NOR_SLEEP_WHILE_WAITING_UNTIL_READY=n (028, −1,59), повтор interrupt отдельно (036), подтверждение на 10 циклах лучшего из двух (037). Кандидаты File для проверки на 5 fabrics — interrupt без read-size 32.
