При кеше 256 обычный целочисленный хеш ячейки лучше «оптимизированного для settings»: у варианта FOR_SETTINGS (zms.c, zms_lookup_cache_pos) позиция = (усечённый хеш имени << 2 | бит данных | бит LL) % размер — при 256 на хеш остаётся 6 бит, биты коллизий отброшены. bench hit/miss 97/43 мс (база 130/75), скан 345 мс. commit выше (0,59 с). Проверить в комбинации: кеш 2048 + FOR_SETTINGS=n и 1024 + FOR_SETTINGS=n.
